# Mage-VL streaming gate は「イベント時刻」と「コンテンツ種別」のどちらに反応するか

Mage-VL の MLX 移植シリーズの検証です。
[Stage 4](../mage-vl-mlx-stage4-codec-native/README.md) で
「codec 入力にすると streaming gate が発火する」ことは確認できましたが、
発火が codec グループ末尾という構造的な位置に集中しており、
**イベント時刻との対応は未確認**のまま残っていました。
この lab は対照実験でそこを決着させます(2026-08-26)。

結論を先に書くと、**発火はイベント時刻に追随しません。**
gate はコンテンツ種別(サッカー中継か、静かな廊下か)を明確に分けますが、
同じ種別の中では「イベントあり」と「イベントなし」を区別しませんでした。

## 目的と問い

- gate の発火はイベント発生時刻に対応するか、それとも構造的・内容的な要因か
- 公式の segment 分割 protocol と codec 経路を組み合わせた構成
  (`inference_streaming.py` の既定)で挙動はどうなるか

## 実験計画

イベントを含む動画と、**同じ被写体でイベントを含まない対照動画**を組にして、
発火パターンを比較します。同じ位置で同じように光るなら構造的、
イベント時刻付近だけ差が出るなら意味的です。

対照動画は LTX-2 で同じ seed(1234)・同じ被写体・イベントなしの prompt で
生成しました。生成スクリプトは前 lab の `output/videos/gen3.sh` にあります。

| 組 | イベントあり | 対照(イベントなし) | 対照の妥当性 |
|---|---|---|---|
| ドア | `door_open`(t≈6.7s にドアが開く) | `door_static`(終始閉じたまま) | **有効**(目視確認) |
| サッカー | `soccer_goal`(t≈6-8s にシュート) | `soccer_idle`(パス回しのみの指示) | **失敗**(下記) |

`soccer_idle` は「シュートなし」と指示したにもかかわらず、
生成結果にはゴール前の攻防が含まれていました。クリーンな対照ではありません。
この点は結論の解釈で考慮します。

## 観測した事実

### 公式構成(codec + segment)での判定

`inference_streaming.py` の既定構成です。4 秒セグメントに分割しました。

| 動画 | 0-4s | 4-8s | 判定 |
|---|---:|---:|---|
| `soccer_goal`(イベントあり) | 0.7907 | 0.6905 | speak, speak |
| `soccer_idle`(対照) | 0.7835 | **0.7786** | speak, speak |
| `door_open`(イベントあり) | 0.0426 | 0.1007 | silent, silent |
| `door_static`(対照) | 0.0789 | **0.1136** | silent, silent |

**コンテンツ種別は明確に分かれます**(サッカー 0.69〜0.79 対 ドア 0.04〜0.11)。
一方、同じ種別の中ではイベントの有無で区別できません。
それどころか、**シュートを含む 4-8s セグメント(0.6905)は、
対照の同じセグメント(0.7786)より低い**値でした。

### 発火位置の構造

canvas は 4 枚で 1 グループを成し、`4k` 番目は単一時刻(I frame)、
`4k+1..4k+3` は複数時刻にまたがります(P frame)。
`p_speak` が高いのはほぼ常に**各グループ末尾**(index 3, 7, 11, …)で、
I frame canvas(index 0, 4, 8, …)は 0.001 前後に沈みます。
これは動画の内容によらず共通でした。

### 副産物: 実行上の落とし穴 2 件

- 公式の segment 分割は末尾に極端に短いセグメント(本検証では 0.04 秒 = 1 frame)を
  生む。codec 経路は group を構成できず `no canvases produced` で落ちる。
  公式スクリプトも処理できないセグメントを skip する作りなので、同じ扱いにした
- subclip を macOS のシステム temp(`/var/folders` 以下)に置くと、
  Docker が共有していないため container から見えない。
  ソース動画と同じディレクトリに置くことで解決した

## 解釈と評価

- **gate の確率はイベント検出に使えない。** 2 組の対照実験で、イベントの有無が
  判定を変えませんでした(1 秒粒度での再検証は後述の続報を参照)。ドアの組(有効な対照)ではイベント canvas が
  突出せず、サッカーの組ではイベントを含むセグメントのほうが対照より低い値でした
- **gate はコンテンツ種別に反応している。** サッカー中継は一貫して speak、
  静かな廊下は一貫して silent です。この分離は明確(0.69〜0.79 対 0.04〜0.11)で、
  種別判定としては機能しています
- これは StreamMind の設計意図と整合すると解釈できます。gate の役割は
  「いま実況すべきストリームか」を判定することであり、
  サッカー中継は継続的に実況対象、静かな廊下はそうではない、という判断になります。
  「ドアが開いた瞬間を検出する」用途とは異なります
- 発火位置がグループ末尾に集中するのは、公式 protocol が
  セグメント境界の logits だけを読む設計と整合します。
  I frame canvas が沈むのは、単一時刻しか含まないためと推測しますが未確認です
- サッカーの対照は失敗しています。ただし結論は主にドアの組(有効な対照)と、
  「イベント区間のほうが対照より低い」という向きの観測に依拠しており、
  対照の不備によって覆る種類の結果ではないと考えます

## この結果が意味すること

当初の関心だった「動画の特定シーンを検出してイベント発火する」機能は、
**この gate だけでは実現しません。** gate が答えるのは
「このストリームは実況に値するか」であり、
「いま何かが起きたか」ではありませんでした。

同種の機能を実現するには、gate の出力ではなく本体 VLM の生成内容を使うか、
別のイベント検出機構を組み合わせる必要があります。

この見通しは後述の続報で実地に確認できました。生成文はイベントとその時刻を
正しく述べており、確率より明確に判別します。

## 続報: 1 秒粒度での再検証(2026-08-26)

上記の対照実験は whole-video と 4 秒セグメントで行いました。その後、
公式互換スクリプトで **1 秒粒度**を試したところ、結論を弱めるべき観測が出ました。

### 訂正: codec は 1 秒セグメントでも動く

本文で「2 秒セグメントは codec が group を構成できず落ちる」と書きましたが、
**誤りです。** 落ちていたのは末尾 0.04 秒の端切れセグメントだけで、
1 秒(24 フレーム)でも通常のセグメントは処理できます。
skip 処理を入れた状態で 1 秒・2 秒・3 秒・4 秒すべて動作を確認しました。

### 1 秒粒度でも、確率はイベントを分離しない

`soccer_goal` と `door_open` を 1 秒刻みで実行した結果です。

| 動画 | 1 秒ごとの p_speak |
|---|---|
| soccer_goal | 0.80, 0.79, 0.81, 0.76, 0.80, 0.92, 0.89, 0.80 → 8/8 speak |
| door_open | 0.40, 0.27, 0.05, 0.26, 0.23, 0.13, **0.15**, 0.07 → 8/8 silent |

door_open でドアが開く 6-7s は 0.15 で、何も起きていない 0-1s(0.40)より低い。
粒度を細かくしても確率はイベントを指しません。

### ただし glass_fall では反応が見えた

`glass_fall`(グラス落下、t≈6.0-7.0s)を 1 秒刻みで実行すると、
イベント区間が最大値になりました。

| 区間 | p_speak | 生成文の要点 |
|---|---:|---|
| 0-1s | 0.02 | (閾値未満) |
| 1-2s | 0.52 | "remains **static** ... no noticeable changes or movements" |
| 2-3s | 0.14 | (閾値未満) |
| 3-4s | 0.49 | "remains **static** ... no noticeable changes" |
| 4-5s | 0.45 | "remains **static** ... no noticeable changes" |
| 5-6s | 0.07 | (閾値未満) |
| **6-7s** | 0.50 | "**Suddenly**, a clear glass container **starts to move, tilting and rotating**" |
| **7-8s** | 0.74 | "a glass object **moving rapidly, creating a blurred effect**" |

確率だけ見ると、イベント開始の 6-7s(0.50)は何も起きていない 1-2s(0.52)より
低く、0.45〜0.52 に団子で分離しません。τ=0.6 にすれば 7-8s だけが残って
「完璧な検出器」に見えますが、それは 1 本の動画に閾値を合わせただけです。

### 判別しているのは確率ではなく生成文

上表で決定的なのは右列です。**「static / no changes」系 3 件と
「Suddenly / moving rapidly」系 2 件に綺麗に割れており**、
6-7s の "Suddenly ... starts to move" はイベント開始そのものを述べています。
フレーム目視で付けた注記(t≈6.0-7.0s)と一致します。

なお生成文も万能ではなく、物体の同定は揺れます
(同じグラスが "pitcher"、"glass with a metal spoon" と描写される)。
一方で**静止しているか動いているかの判定は一貫して正確**でした。

### 結論の修正

本文の「発火はイベント時刻に追随しない」は、
**「gate の確率はイベント時刻を指さない。ただし動きの大きいイベントでは
生成文がイベントとその時刻を正しく述べる」**に改めます。

反応の差は動きの大きさによると推測します。落下するグラスは画面内で速く大きく動き、
ドアの開閉はゆっくりで局所的です。gate が bit 配分(= 変化量)由来の特徴を
見ていることと整合しますが、これは仮説であり検証していません。

実用的には、gate を低い閾値(0.3 程度、または 0)で足切りに使い、
**判定は生成文で行う**構成になります。

## 未確認事項と制約

- 検証は LTX-2 生成動画 4 本(2 組)、各 8 秒のみ。実写映像は未検証
- `soccer_idle` はクリーンな対照になっていない
- イベントは「ドアが開く」「シュート」の 2 種のみ。gate の学習分布に含まれる
  種類のイベント(得点、反則など)を意図的に作り分けてはいない
- 8 秒という長さは公式既定のセグメント長(8 秒)と同じで、
  1 動画あたり 2 セグメントしか取れていない。長尺での挙動は未確認
- I frame canvas の値が沈む理由は未確認
- 閾値は公式既定の 0.5。別の τ でも結論は変わらないと考えるが、
  イベント有無で値の大小関係が逆転しているため、閾値調整では解決しない
- gate の学習データと想定運用は公開情報からは詳細不明
