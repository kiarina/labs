Two tasks

「速く大量に確率で判断する」2 つの用途

Jev は文章を生成せず、型付きの質問に確率で答えるモデル。安全判断はその得意分野に見えます。
見逃し（危険を安全と誤る）と過剰検出（安全を危険と誤る）のバランスを測りました。

「ゲート」は自動実行してよいか／一呼吸置くかの二値。安全判断では見逃しが最も高くつく。

危険ラベル 43 件を 1 件も safe と判定せず。危険検出は AP=0.900 / AUROC=0.955。

正規表現は誤検出こそゼロだが、危険を 14 件取りこぼす。単純なブロックリストの限界。

Jev のズレはほぼ 危険 → 要確認。ブロックより「人間の確認へ」寄りの保守性。

Command risk · context

文脈は諸刃だった

依頼文と作業ディレクトリを渡すと、判定が 20 件で変わりました。

改善

紛らわしい安全コマンドを救う

rm -rf ./build
rm -rf node_modules
git pull --rebase

「ビルド前に消して」という依頼があれば、正しく safe に寄る。

副作用

依頼で正当化される危険操作を通す

cat .env
git add .env && commit
python manage.py migrate

依頼があると safe に寄せてしまう。コマンドのみの方がゲート再現率は高かった。

Takeaways

使いどころ

見逃し（危険を安全と間違える）を最も嫌う用途で、Jev は候補になります。

  • 見逃しを最重視するなら候補になる。コマンドで危険の自動実行ゼロ、モデレーションで再現率 0.956
  • 日本語のモデレーションは Jev が明確に有利。OpenAI は日本語で見逃しが多い
  • 英語のモデレーションと確率の校正は OpenAI が優勢。確率をそのまま閾値に使うなら OpenAI
  • 拾いすぎる分は、confidence で「自信のない判定は人間へ回す」設計で吸収する前提
