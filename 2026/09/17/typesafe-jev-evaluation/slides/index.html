What is Jev

文章ではなく、型付きの「判断」を返す

評価したい内容（state）と、型を決めた質問を送ると、確率つきの答えが返ります。
チャットはできませんが、そのぶんコードの if 文にそのまま使えます。

STATE

文字列 / JSON / 配列

問い合わせ、記事、アプリの状態など。テキストのみ

JevPOST /v1/systemone
ANSWERS

確率・選択・スコア

質問ごとに型どおりの値。出力トークンは無料

NOUL

Yes / No

「急ぎか？」→ yes である確率 0.95

CHOICE

選択肢から 1 つ

「担当部署は？」→ billing と各選択肢の確率・確信度

SCORE

段階評価

「苛立ちの度合いは？」→ 1.03（Calm / Frustrated / Very angry）

Response

レスポンスは小さく、そのまま使える

{
  "model": "jev-1.13.0",
  "answers": {
    "is_urgent": { "type": "noul", "noul": 0.95 },
    "department": {
      "type": "choice", "choice": "billing", "confidence": 0.83,
      "probabilities": {
        "billing": 0.89, "technical": 0.11, "sales": 0.0
      }
    },
    "frustration": {
      "type": "score", "score": 1.03, "confidence": 0.95,
      "probabilities": { "0": 0.0, "1": 0.96, "2": 0.04 }
    }
  },
  "usage": { "input_tokens": 426, "output_tokens": 73 }
}

Noul には confidence が付かない。
確信度が返るのは Choice と Score だけ。

課金は入力トークンだけ。
$0.042 / 100 万 token。1 文字の state でも約 273 token かかる。

models には alias しか出ない。
jev-latest と jev-preview。応答の model で実際の版が分かる。

Latency

長くしても、ほとんど遅くならない

入力を 1.4k → 32k token に増やしても、応答は約 0.2 秒から 0.3〜0.45 秒へ伸びるだけ。
国内の開発機からの往復時間（ネットワーク込み）です。

Characters that fit

日本語で入るのは、約 3 万文字

上限はトークン数で決まるので、何文字入るかは言語しだい。日本語と中国語は 1 文字 ≈ 1 token、英語は 1 token ≈ 5 文字。

Languages · classification

質問を英語にすれば、8 言語とも英語と同じ判断

言語部署 · 英語の質問部署 · 各言語の質問英語との差言語判定

SaaS への問い合わせ 16 件を 8 言語に翻訳し、担当部署（4 択）・急ぎか・苛立ちを判定。

英語の質問なら 16/16 × 8 言語。確率も英語版と平均 0.02 未満の差。

質問も翻訳すると差が 0.02〜0.04 に。「チーム全員がログインできない」を 5 言語で account と判定。選択肢の説明に「ログイン」を入れた設問側の曖昧さが境界を越えさせた。

繁体字の短文は簡体字と取り違えることがある（16 件中 2 件）。

Languages · long context

上限近くの長文でも、事実を取りこぼさない

業務日誌に「北側倉庫室のコードは 4817」を埋め、方角だけ違う「南側…9352」も混ぜました。
長さ 4 通り（上限の 3〜97%）× 位置 5 通り × 有無 2 通り ＝ 各言語 40 ケース。

埋め込みあり（positive）なし・南側だけ（negative）線 = 40 ケース中の最小〜最大の範囲、点 = 平均
320/ 320

コードを答える Choice の正解数。needle がなければ not_stated を選び、南側のコードに引きずられなかった。

ただし題材は易しめ。10 文の繰り返しの中の目立つ一文で、自然な長文や複数箇所の推論は未検証。

Repeatability

ほぼ安定。ただし完全に決定的ではない

±0.004

同じリクエストを 10 回送ったときの確率の標準偏差（平均）。最大でも 0.056。

1/ 80

10 回の中で選択が入れ替わった系列。de の「ログインできない」で 1 回だけ account。

10/ 10

上限 97% の長文で同じ答え。Noul の標準偏差は 0〜0.0075。

確率 0.4〜0.6 の判定は、同じ入力でも入れ替わりうる。 confidence や確率の差で「保留」に回す設計を前提にする。

Takeaways

使いどころと、まだ分からないこと

分かったこと

  • 多言語の入力は英語の質問で扱うのが安定。state の言語差はほぼ出ない
  • 日本語は 約 3 万文字で上限。超えたら 400 を見て分割する
  • 1 回に 数百〜2,000 問を投げても 1 秒前後。質問はまとめて送る
  • 0.2 秒・$0.042 / Mtok なので、全件・常時の判定に向く

未検証

  • 自然な長文に紛れた事実、複数箇所を組み合わせる推論
  • LLM（Claude Haiku など）との精度・コスト比較
  • レート制限（429）の挙動。負荷をかける試験は避けた
  • 翻訳データはネイティブ校正なし。ラベルには筆者の主観を含む
