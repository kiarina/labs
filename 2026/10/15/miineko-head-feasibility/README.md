# Tripo P2.0 の頭モデルを表情制作の出発点として評価する

## 現在の結論

採用した見た目はクラウドで作成した **V2 centered-highlights**。頭の表情試作 V2 の口・目・瞬きと、
ハイライトの高さ・大きさを保持し、ハイライトの横位置だけを黒目の中央へ移した。
採用済みの動く顔頂点・口・ハイライトを保持したメッシュ整理と密度最適化を終え、実際の MToon 材質を持つ頭単体 GLB を出力した。
今回の頭の準備は完了。材質の陰影は従来より平坦で、形状保持とは別に確認する必要がある。
完成 VRM やランタイム検証済みのモデルではない。
開眼の黒目を正円にした別の比較版も作成済みだが、正式採用は未確認。採用済みの元版を置き換えない。

## 目的と評価方法

画像に描かれた顔から脱し、形を変える表情を持つ VRM を作るための元メッシュとして使えるかを調べる。
四面入力による頭だけの生成を 1 回実施し、原本 FBX を保全して Blender で頂点・面・連結部品・辺の接続・顔の形を検査する。
過去の [VRM 表情研究](../../../09/28/miineko-vrm-expression/README.md) は関連研究であり、このモデルの入力や実装には依存しない。

## 入力と生成条件

- 前・左・右・後の 4 枚、各 1254×1254 RGB PNG。サイズは順に 1677065・1799250・1759147・1723509 bytes
- Tripo の Multi-view 専用 4 枠、SmartMesh P2.0、quad、12000 polygons 指定、生成数 1、非公開
- 生成 1 回、100 credits 消費。追加の texture・retopo・rig・再生成は実施していない
- 出力は FBX + Blender。原本は 496000 bytes、FBX 7400
- 原本 SHA-256: `a9c0071813c46eb4f97b6fdf3af911dae641c9af08f6a836a92803d690cb3b2f`

## 原本の検査結果

2026-10-15、クラウド環境の Blender 5.2.2 LTS で検査した担当者の実測報告を記録する。
この文書を保存した環境で再実行した結果ではない。クラウドに取得した FBX と原本の SHA-256 は一致した。

| 項目 | 観測値 |
| --- | --- |
| 頂点 | 12540 |
| 面 | 12921（quad 11567、三角 1354） |
| オブジェクト | 1 |
| 連結部品 | 9（頭、耳 2、目 2、ハイライト 2、鼻、口） |
| UV・画像テクスチャ・頂点色 | なし |
| 骨・shape key | なし |
| 境界辺 | 617 |
| 3 面以上で共有する辺 | 1 |
| 耳の面向き不整合 | 7 辺 |

目・鼻・口は実ジオメトリ。頭と目には小穴があり、目には不均一な三角形と頂点集中がある。
境界辺には意図的な接合部の開口も含まれるため、617 辺すべてを欠陥とは扱わない。
まぶた・口腔はなく、口は高密度な線状立体で、開閉に使える上下唇構造ではない。

## 過去モデルによる見た目の参照（最新実験の確定仕様ではない）

追加の `miineko.blend` は、オーナーが口の開き方・平らな目とハイライト・閉じ目の理想に近い参考として提示したもの。
PBR、メッシュの乱れ、瞬きの互換性に問題があるため、見た目の目標と実装方法を分けて扱う。
クラウド担当者が Blender 5.2.2 で自動スクリプトを無効にし、原本を保全して検査した報告を記録する。
この文書の保存環境に画像やモデルを転送したものではない。

| 対象 | 見た目の目標 |
| --- | --- |
| 目 | 顔に沿った浅い楕円 |
| ハイライト | 目の左上にある平たい白丸 |
| 口 | 薄い W 字の猫口を残し、その下に開く赤い丸い U 字 |
| 閉じ目 | 中央が太く、端が細い、上向きの弧 |

既存ファイルには口と瞬きの native shape key がない。口と瞼の重ねメッシュに、UV の移動・画像 alpha・頂点色を使っている。
耳の `Surprise Ears Up` だけは shape key がある。
口の開きは既存 shader の値を試して見た目を確認した。閉じ目には崩れが残り、意図した弧は packed texture から確認した。
閉じ目の正常動作を再現できた、とは扱わない。

## 頭の表情試作 V2

クラウド担当の完了報告を記録する。原本を変更せず、追加 credits なしで作成した。
この文書を保存した環境ではモデルを加工・検証していない。

- まぶた・口周囲を頭へ接合し、一定トポロジーの `blinkLeft`・`blinkRight`・`aa` を作成
- 平らな黒目と白いハイライト、弧状の閉じ目、赤い U 字の浅い口内を作成
- 途中状態、左右、組み合わせと、正面・斜め・側面を確認。側面の半目で黒目が露出する問題を V2 で改善
- 計 49,834 頂点・49,369 面、13 メッシュ

## 見た目の比較と最新実験

口はオーナーが了承した一方、閉じ目が細いことと半眼の可愛さに指摘がある。
V3 A は通常の線形 blink だけで太い閉じ目を作る案、V3 B は途中補正で笑う半眼を作る案。
B の途中補正は標準 VRM blink だけでは再現できない。V3 A/B は比較案であり、採用する見た目は V2 centered-highlights。

参考指定された [Pikachu の動画](https://www.youtube.com/shorts/zre8xtXaxjs) はクラウドで再生できていない。
映像を見た、動きを比較した、とは扱わない。

V2 を基にハイライトだけを内側左右対称にする実験を行い、その後に高さを維持して横位置を黒目の中央へ変更した。
最新の centered-highlights は、口・目・瞬き・ハイライトの高さと大きさを保持し、横位置だけを中央化したもの。
全閉の白漏れも検査済み。この V2 centered-highlights の見た目を採用して本番準備を進める。

## 開眼の黒目を正円にする比較実験（未採用）

オーナーの「開いている時の目なんだけど、黒目正円になる？」という依頼に基づくクラウドの追加実験。
採用済み centered-highlights V2／MToon 頭の元版を保全し、別の比較版を制作した担当者の報告を記録する。

- 開眼の高さを保ち、横幅を 15% 拡大。正面輪郭を半径 0.115 の正円にした
- ポリゴン外接幅・高さの差は 0.02% 未満。閉眼の弧の終点差は 0
- 口と元のアニメーションは不変。ハイライトの水平中心・高さ・サイズを保ち、奥行きだけ新しい黒い面に合わせた
- 半眼は少し横広になる
- 斜め閉眼で出た黒い裏面のはみ出しを修正し、開眼・半眼・閉眼・斜めのレンダーを確認
- 閉眼のハイライト遮蔽は各角度 616 本の検査で通過

成果は `miineko-round-open-eyes.blend`、`miineko-round-open-eyes-preview.png`、`README.txt`、`verification.json`。
クラウドの `head-round-open-eyes/` が保有する。モデルと画像をこの lab の作業環境へ転送・検証したものではない。
正円版は本人確認前の比較実験で、正式採用ではない。半眼の横広がりも含めて見た目の判断が必要。
この結果から全角度や実ランタイムの保証を広げない。

## 残件と未検証範囲

- 体・リボン、humanoid rig
- VRM 出力と VRM 表情 binding
- 実ランタイムでの表示・表情検証
- 全角度の見た目の保証

頭単体 GLB と MToon 材質の検証を、完成 VRM や全身アバターの検証と混同しない。

過去モデルの壊れた実装を継承せず、通常の MToon・静的 UV 1 層・morph を使う方針を保つ。
見た目の採用と、上記の実装・互換性検証の完了を区別する。
今回の準備では全身制作・有料 Tripo 追加生成・公開は行わない。

## 証拠の所在と限界

検査画像・中間モデル・スクリプトの一式は検査したクラウド環境が保有する。
この lab にはバイナリや画像を複製しておらず、第三者による完全な追試に必要なスクリプト一式もまだ収録していない。
原本・検査画像の非公開の取得先、実行環境をまたぐ受け渡しと本人への提案状況は agent の担当タスクが管理する。
