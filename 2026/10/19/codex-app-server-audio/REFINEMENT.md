# 話者IDの誤分割と音声・文字時刻の対応の改善

## 検証の範囲

[初版の接続維持ASR](PERSISTENT_ASR.md) で観測した、同じ話者を別IDにする誤りと、最初の文字差分へ依存した時計校正を改善する。prototype は変更しない。話者識別、音声時計の校正、文字を単語の音声位置へ割り当てることは別の評価とする。

## 話者IDの改善

照合閾値0.45は変更せず、新しいIDを登録する条件を厳しくした。

- 新規登録には2秒以上の区間を使う。
- 既存話者との類似度が0.35〜0.45の迷う範囲では、3秒分になるまで新規登録を保留する。
- 1.5秒未満の短い観測は、既存IDに一致しても登録用の埋め込みへ追加しない。
- 後から十分な音声でIDができたら、保留した過去区間を再照合する。
- 本文は待たせない。話者IDの決定は遅くなる場合がある。IDは試験内のローカルなクラスタであり、身元や話す順の番号ではない。

[ローカルモデル比較](results/speaker-refinement-offline.json) はクラウド推論・マイクを使わず、同じ観測ベクトルを旧・新ルールへ渡したもの。素材は既存の2話者会話で、順序変更と1話者だけの切り出しも作った。負の対照として macOS の Samantha で別の声を生成して加えた。別の人の実マイクや別コーパスでの評価ではない。

| 入力 | 期待する人数 | 旧ルール | 改善ルール |
| --- | --- | --- | --- |
| 元の2話者会話 | 2 | 3 | 2 |
| 順序を変更した会話 | 2 | 2 | 2 |
| 1話者の発話だけ | 1 | 1 | 1 |
| 別の合成音声を加えた会話 | 3 | 4 | 3 |

各条件の発話中心点のIDも、人物番号の入れ替えを許せば元の話者の区別と一致した。照合用の人物順序と境界は評価だけに使い、オンラインの照合ルールへ正解を渡していない。境界は先行の全区間話者分割をもとにした近似で、単語時刻の正解データではない。

## 文字に依存しない時計校正

[OpenAI Docs の sideband説明](https://developers.openai.com/api/docs/guides/voice-server-controls) では、入力音声のコピーは `session.input_audio.append`、出力音声コピーは時刻付き `session.output_audio.delta` とされる。今回のChatGPT認証経路でも [両イベントを確認](results/refinement-protocol-probe.json) した。入力コピーは mono PCM16 / 24kHz だが、入力自体に時刻はない。

改良版は次のように照合する。

1. 端末が予約送信するPCMと、そのnative sample clockを localhost の制御サーバーへ参照として渡す。OpenAIへの音声送信はWebRTCの1経路だけ。
2. 上流から返る入力音声コピーと参照波形を、共通3kHzグリッド上の正規化相互相関で照合する。
3. 相関0.65以上、競合する一致点との差0.12以上の、複数の一致点だけを時計アンカーとして採用する。
4. 入力コピーの累積サンプル数と、同じsidebandに来る出力時刻の進み方を照合する。時刻の不整合が大きければ校正は採用しない。
5. 複数アンカー間を区分的に補間する。100msを超える位置の不連続や大きな速度差・4秒を超える空白では校正区間を分け、確認できた区間内だけを使う。内部の不連続は跨がず、最外周の範囲外は最大1秒まで、それより外は保留する。

最初の認識文字や正解文を時計の推定に使わない。ただし入力コピーには公式の時刻がないため、入力・出力イベントの相対的な進み方には仮定が残る。これはサンプル精度の厳密同期の保証ではない。

[独立の実接続プローブ](results/refinement-clock-probe.json) は3つの波形一致点で時計を校正できた。音声一致点同士の差はほぼ一定で、同一sideband上の出力時計との差の幅は約10msだった。実装の不確実さとして最低100msを保持する。

[オフライン対照](results/refinement-clock-controls.json) では、Opusで符号化・復号した音声に既知の時刻差を与え、先頭1.5秒を欠落させても後の波形で位置を復元できた。無音・繰り返しによる曖昧な波形・不整合な出力時計は採用しない。この人工条件の誤差0msを実機の精度保証には使わない。

実接続の13アンカーを使った [実装そのものの再生検査](results/refinement-runtime-binding.json) では、アンカーを1つずつ除いて補間する最大差は約19.6ms、最後の固定オフセットを全区間へ使う場合は最大120msだった。これは**音声アンカーの内部整合性**の検査であり、単語位置や外部の正解時計に対する誤差ではない。

## 文字と話者の対応に残った限界

音声時計を合わせても、上流の文字差分時刻は厳密な単語境界ではない。[公式の説明](https://developers.openai.com/api/docs/guides/live-conversations) でも概略の区間とされる。1つの差分に話者交代を跨ぐ内容が含まれる場合もある。

[最初の改良版の実接続](results/refined-asr-fixture.json) は、話者2クラスタ・44差分すべてが取得中に到着し、入力破棄・予約遅れ・応答音声・委譲は0だった。しかし交代付近の語を次の話者へ付ける例が残った。

そこで、文字の推定範囲だけを一点的に見る方式をやめ、不確実範囲全体にある話者候補を見る。複数候補や時計範囲外は保留する。境界ガード1秒を改良版の保守設定にするが、全音声で誤対応しない保証はない。

同じ保存データへ本番用のDart関数を適用した検算は次のとおり。正解の話者は共有会話の内容境界に評価用マーカーを置いたもの。マーカーは照合の評価にだけ使い、時刻校正・話者割り当てには使っていない。

| 境界ガード | 正しい対応 | 誤対応 | 保留 |
| --- | --- | --- | --- |
| 200ms | 27 | 4 | 13 |
| 600ms | 19 | 1 | 24 |
| 1秒 | 11 | 0 | 33 |

44差分の1件は時計アンカー範囲外だった。誤対応を避けると多くが保留になるため、**全ての文字へ正しい話者を自動付与する問題は未解決**。単語レベルの厳密な対応が必要なら、別の音声・文字アラインメントや、それを返せるASR経路の評価が必要になる。波形による時計校正だけで解決したとは扱わない。

## 実装と実行

- `asr/app/lib/speaker_tracker.dart`：登録を保留する照合ルール。
- `asr/app/lib/audio_time_mapper.dart`：時計補間と境界ガード。
- `asr/app/lib/refine_offline.dart`：ローカルモデル比較。
- `asr/app/lib/refine_binding_replay.dart`：保存した差分を実際の対応付け関数で再生。
- `tools/audio_clock.py`：波形とsideband時計の校正。
- `tools/refined_asr_server.py`：改良モードのローカル制御。

Flutter / record / WebRTC / ONNX / Codex CLI / モデルは [接続維持版](PERSISTENT_ASR.md) と同じ。波形照合には、調査時の安定版 NumPy 2.5.4 を `tools/refined_requirements.txt` に追加して固定した。以前の依存pinは変更しない。

```sh
mise run refinement-offline                    # クラウド推論なしの比較
PERSISTENT_AUTOTEST=1 mise run refined-asr      # 改良版の共有素材の実接続
mise run refined-asr                          # 改良版の実マイクUI
```

`REFINED_ASR=1` のときだけ新ルールを使い、旧方式は従来のtaskで比較できる。先読み1秒・250ms hop・ネイティブ予約供給・本文の即時表示は維持する。本文は話者IDや時計の確定を待たない。

入力コピー・参照PCM・埋め込みはRAM内だけで保持し、試験終了時に破棄する。生音声や実マイクの会話文を結果ファイルへ保存しない。保存するのは校正アンカー・相関係数・ID・状態・計測値で、共有素材の試験に限って既存素材の文字列を保存する。

## 最終組み合わせの試験

[最終組み合わせの実接続](results/refined-asr-fixture-final.json) でも話者2クラスタ、41差分すべてが取得中に到着し、予約遅れ・入力破棄・応答音声・委譲は0だった。しかし11アンカーの途中に約200msの不連続があり、当時の「全アンカーへ一つの連続性条件を課す」判定は不合格となって全差分を保留した。この結果は修正せず残している。

その後、校正を連続した範囲ごとに分ける実装へ修正し、同じ保存イベントを最新のDart関数で [再生検査](results/refinement-final-binding.json) した。時刻の支えがない15差分は保留し、境界ガード1秒では41差分中8件を対応付け、評価上の誤対応0・保留33件になった。修正後の範囲分割は保存イベントでの検査とrelease buildまでで、実接続をさらに繰り返してはいない。

今回の改良版について新たな実マイク複数人・長時間の評価は行っていない。本文表示の速さは両実接続で取得中の表示を維持したが、時刻校正方式が変わったため、旧版の「単語位置を仮定した表示遅延」と数値を単純比較しない。後からIDを付け直すため、本文より話者IDが遅れる場合もある。

## 結論

話者の誤分割は、4つのローカル条件と2回の共有素材の実接続で改善した。音声の位置合わせも、文字に依存する原点推定から、波形アンカー・時計の連続範囲の照合へ改善できた。

ただし**音声時計が合うことと、単語ごとに正しい話者を付けることは別**で、後者は未解決。誤対応を減らす保守設定では、多数の差分が保留になる。全ての文字を自動で話者に結び付ける用途には、この改良だけでは不十分。必要なら単語レベルの音声・文字アラインメントを別途評価する。

[保存結果の検算](results/refinement-validation.json) の ok は、改善と失敗・保留を含めて観測値が整合するという意味であり、完全な話者付きASRの合格判定ではない。prototype は変更していない。
