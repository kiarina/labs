# WebRTC を維持する VAD・話者ゲート付き ChatGPT ASR

## 問いと評価方法

区間別に接続を作り直す [前試験](SEGMENTED_ASR.md) と区別し、1つの ChatGPT 認証 WebRTC 接続を試験中維持する。record の入力をローカルの VAD・話者変化検出で選び、認識に必要な元音声だけを送る。文字起こしの音声時刻で元区間・話者IDへ結び付ける。prototype は変更しない。

評価条件を実行前に定める。

- 接続が1回で、取得中に文字起こし差分が表示される。
- 250ms hop の解析が送信に間に合い、古い区間の直列再送が発生しない。解析遅れによる無音置換や送信欠落は計測し、隠さない。
- 文字起こしを到着時刻で次の話者に付けず、元音声時刻へ対応付ける。境界・時計の不確実さ・未確定話者は明示する。
- 応答音声の有無を消音前PCMとassistant差分で判定する。
- 表示遅延の中央値・p95と本人の体感を確認する。暫定の目安は中央値2秒以内・p95 3秒以内だが、音声時刻の整合性を確認できなければこの数字で合格にしない。

## 文字起こしイベントの確認

公開 Live API は `session.input_transcript.delta` に `start_ms` / `end_ms` を持つ。[OpenAI Docs](https://developers.openai.com/api/docs/guides/live-conversations)。一方、本 lab の Codex CLI 0.163.0 / ChatGPT 認証経路は旧 `input_transcript.added` 形式。

[実イベントの短い試験](results/persistent-timing-probe.json) で、旧形式のトップレベルにも `start_ms` / `end_ms` があり、本文は `item.text` にあることを確認した。標準 app-server の transcript delta 通知は時刻を捨てるため、localhost sideband adapter で時刻を維持してアプリへ渡す。上流の認証値・call ID・item IDは保存しない。共有素材による確認で、実マイクの会話ではない。

これらの時刻は概略の差分区間であり、正確な単語境界・発話完了保証ではない。境界を跨ぐ文字列を無理に1話者へ割り当てない。

## 入力と処理

- 同じ lab のモデル・外部入力ブリッジを使う。Flutter 3.47.2 / Dart 3.13.2、record 7.1.2、flutter_webrtc 1.6.2+hotfix.4、flutter_onnxruntime 1.9.0、macOS 14以上。
- VAD：Silero、16kHz / 512 samples、閾値0.5、前後200msを保持。
- 話者ゲート：pyannote、250ms hop、過去最大6秒＋先250msの窓。話者区間かつVADの範囲にある10msフレームだけを送る。その他は同じ時間幅の無音を送って時間軸を維持する。
- 固定先読みは1秒。Dartは250ms単位で選別済みPCMを予約し、ネイティブの音声時計が10msずつ供給する。解析が締切に間に合わない区間は無音になり、遅れと破棄をカウントする。遅い区間を後から割り込ませない。
- 話者ID：ECAPA、類似度0.45、短い新話者は未確定にする。前試験と違い、低類似度の短い発話を既存話者へ強制的に寄せない。IDは各試験内のクラスタであり人物の身元ではない。
- 本文は差分到着時に表示し、後から話者情報を暫定更新する。確定を待つ間も本文表示を止めない。

## 時刻の対応と計測

ネイティブの外部音声デバイスに予約したsample clockと、元音声の10msフレームを送信台帳へ記録する。上流と端末の時計の原点差は、最初のVAD開始と最初の入力文字差分を基準として推定する。補正した `start_ms` / `end_ms` を台帳へ照合し、元音声時刻へ戻す。話者解析窓の結果には更新時刻を持たせ、最新の解析で暫定ラベルを更新する。話者境界の前後200msを曖昧として候補が複数なら保留する。

実際には上流と外部デバイスの時計の原点は一致しなかった。最初のVAD開始と最初の文字差分が同じ音声位置を指すという仮定を使うため、これは推定の照合であり、正確な単語アラインメントではない。表示遅延の中央値・p95も推定値として扱う。共有素材で後続の複数の話者の文字列との整合を検査し、実マイクでは本人の評価と区別する。最初の認識が欠ける／大きく遅れる場合には原点推定が誤る可能性が残る。

## 実行

```sh
PERSISTENT_AUTOTEST=1 mise run persistent-asr # 共有素材の実接続試験
mise run persistent-asr                    # 実マイク30秒の体験
```

task が shared assets の取得、モデルhash検証、Flutter build、localhostの制御サーバーを用意する。認証はChatGPTのみ。公開APIキーへのフォールバックは使わず、Thinkerは起動しない。音声はWebRTCで直接送り、制御・時刻付きイベントだけをsideband adapterが中継する。

共有素材は前2秒・後3秒の無音を加えた約19秒。実マイクは30秒取得。終了後に最後の差分を待つ時間があるが、本文は取得中から表示する。実マイクの録音・本文・埋め込みは保存せず、時刻・クラスタID・遅延・状態などの計測値だけを保存する。

## 結果

最初の Dart 10ms timer / 先読み1.3秒の試験は、接続1回で37差分が取得中に届き、受信の非ゼロ音声は0だった。しかし、Dart側のタイマーで370フレームが飛び、ゲート未準備67フレームがあり、時計原点を補正せず話者・遅延を誤って対応付けた。[失敗を含む初回結果](results/persistent-asr-fixture-first.json) は保持し、採用の根拠にしない。

改善版はネイティブ予約供給を使い、時計原点を推定して照合する。区間別方式の結果は上書きしない。


### ネイティブ予約供給・共有素材

[修正版の結果](results/persistent-asr-fixture-native.json) は接続1回、41差分すべてが取得中に到着。19.171秒の入力から14.34秒の元音声を送り、残りは無音化した。予約遅れ・native underflow・Dart timer skip・音声バイト破棄は0、応答音声・assistant差分・委譲も0。250msごとのゲート処理は中央値96.1ms、最大155.7ms。

時刻原点の推定補正後の表示遅延は中央値2,158ms・p95 2,450ms。最初のVAD検出から最初の文字表示までは2,660ms。最初の文字の開始位置をVAD開始へ合わせる仮定を含むので、正確な単語末尾からの遅延ではない。初期目安の中央値2秒はわずかに超え、p95 3秒は下回った。

話者は本来2人に対して3クラスタ。「もし」「改札」「カフェ」「マフラー」の4つの照合点は期待したIDに対応したが、「電車」「寒い」の再登場した1人目が speaker-3に分かれた。新クラスタを作ったときの最高類似度は0.441で、閾値0.45を少し下回った。1つの素材へ合わせて閾値を下げる修正は行わない。話者識別の完全な成功とは扱わない。

### 実マイク1人・30秒

[実マイクの計測値](results/persistent-asr-real-mic.json) は30秒取得、301 callback、元音声29.985秒。1接続で43差分が届き、40件は取得中に表示された。選別後に送った元音声は17.25秒、同時間幅の無音へ置き換えたのは13.25秒（終了用の無音を含む）。話者は1クラスタ。40差分を speaker-1 へ暫定対応付け、3差分は送信音声との重なりがないため保留した。会話文・録音・埋め込みは保存していない。

推定表示遅延は中央値1,628ms・p95 1,875ms。最初のVAD検出から最初の表示は1,952ms。応答音声・assistant差分・委譲は0。ゲート処理は中央値194.4ms・最大304.1msで、250ms hop を超える呼び出しもあった。1フレーム（10ms / 960 bytes）の予約遅れと破棄があり、完全な欠落ゼロではなかった。旧Dart timer型のような累積フレーム飛びは0。

入力は最大30秒、解析の窓・予約キューには上限を設けている。現時点の実マイク確認は1人のみで、2人の共有素材での再登場の識別ミスを解消したわけではない。


## 本人評価と結論

本人が1人で実マイク30秒を試し、**「速さも内容も実用的」**と評価した。接続を維持し、ネイティブの時計で選別済み音声を供給する方式では、今回の条件で実用的なASR体験を確認できた。区間ごとに接続し直す方式の評価とは分ける。

ただし、複数話者については共有素材で同じ人の再登場を別IDにした誤りがあり、実マイクでも3差分を保留した。話者IDは推定の時刻対応・クラスタリングによる暫定値であり、全差分の正しい話者付き文字起こしが完成したわけではない。実マイクの複数人、長時間、時計原点の自動校正、欠落ゼロ、無発声の構造的な保証は未検証／未達。1人・30秒の体験評価を全条件へ一般化しない。prototype は変更していない。

[保存結果の検算](results/persistent-asr-validation.json) の ok は、失敗・未確定点も含めた観測値の整合性を示す。話者識別の完全性や厳密な時計同期の合格を意味しない。
