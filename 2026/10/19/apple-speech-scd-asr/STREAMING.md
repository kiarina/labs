# 逐次SCDによる早期の区間確定

## 問い・事前条件

無音500msまたは最大6秒でVAD塊が終わるのを待つ初版と比較し、話者変化を音声到着中に検出して
確定済みの左区間をSpeechAnalyzerへ先に渡す。prototypeは変更しない。

同じ共有音声・モデル・native ASRを使い、旧baselineと逐次方式を各1回比較する。
全区間を既知の境界へ切るのではなく、両方ともVAD/SCDを実推論する。
評価は区間末尾→表示、SCD確定までの先読み、ASR時間、文字の欠落・重複、境界位置、話者候補/保留。
正解は共有素材6発話の文を評価にのみ使い、SCD・ASRへ渡さない。

初期設定は250ms hop、最大8秒の過去窓、350msの先読み、同位置±150msを連続2回確認、
右側の新話者が200ms以上、左側区間が500ms以上。ゼロ遅延の境界検出とは扱わない。
pyannoteのローカル話者番号は窓ごとに入れ替わるため、窓内の変化位置だけを候補として追跡する。

無音は終端用fallbackとして500msを維持。1人が連続して話し続ける場合は話者変化がないため、
最大15秒の安全な上限か停止操作で区切る。これは話者変化で待ちを省く評価であり、逐語字幕ではない。
SpeechAnalyzerはASR専用キューへ分離し、ASR完了の待ちで次のSCD推論を止めない。

短区間・重なりで不確実な話者IDを強制しない。SpeechAnalyzerへの区間ID対応と、話者分類の正解は別に扱う。

## 実装と比較結果

`app/lib/streaming_scd.dart` を追加し、体験アプリの既定を逐次SCDへ変更した。
「話者変化で早期確定（逐次SCD）」をOFFにすると旧6秒方式へ戻る。切替は停止・回収完了後のみ。
recordは一度だけ取得し、VADの32msフレームを処理しながらSCDの250ms hopを実行する。
窓は受信済みの過去8秒。既に確定した音声も過去文脈として保持するが、ASRへ再送しない。
音声の保持は未確定部分を含め最大17秒相当、ASR待ち最大12区間。超過は明示的に停止する。

同一日本語14.171秒・2話者の6発話、各方式1回。表示時刻はテキストを正解の6発話へ
Levenshteinで整列し、その発話に対応した最後の文字の到着を比較した。
区間数が7対6と違うため、単に各ASR区間の待ち時間を平均した値ではない。

| 指標 | 旧6秒方式 | 逐次SCD（過去8秒保持） |
| --- | ---: | ---: |
| ASRへ渡した区間 | 7 | 6 |
| 6発話の末尾表示中央値 | 2605ms | **1009ms** |
| 同最大 | 5375ms | **1159ms** |
| ASR待ち中央値 | 100ms | 107ms |
| CER | 2.33%（2/86字の欠落） | **0%（0/86字）** |
| 話者候補 / 未確定区間 | 2 / 2 | 2 / 0 |
| 文字整列上の複数人物を含む区間 | 0 | 0 |

逐次方式は5か所を `scd_change` で確定し、最後の発話は入力停止で確定した。
SCD境界の確定待ちには350msの先読みと2回確認、推論・スケジューリングが加わる。
5つの交代位置の末尾表示は約0.98〜1.16秒。最後の発話は停止で約186ms。
文字は全体で一致し、元の話者区分とIDも番号の入れ替えを許せば整合した。
ただし同じ短い素材だけの評価で、実マイクや一般的な話者識別精度の保証ではない。

逐次SCDは51回、推論中央値約32ms。旧方式の結果に記録したonline回数0は、
旧方式がSCDを使わないという意味ではない（旧方式はVAD塊ごとにSCDを呼ぶ）。
推論の頻度とCPU負荷は増える。長時間の熱・メモリ・電池、低速端末でのキュー遅延は未確認。

## 失敗と対照

### 過去文脈を短く切り捨てた初回

最初は確定済み区間の約1秒前からだけを解析窓へ残した。
表示中央値は999msへ改善したが、2番目の境界が4.416秒になり、
「そっちは」の末尾1文字が次区間の「あ、こっちは…」に分かれた。
全体CER1.16%、文字整列上は1区間が複数の人物の内容を含み、2発話目の末尾表示は約3.59秒となった。

`results/online-streaming-short-context.json` と `online-comparison-short-context.json` を保存。
過去文脈を8秒窓へ保持する方式に修正すると、その境界は4.703秒となり、同素材で語尾分割が消えた。
350ms・2回という設定を、全入力で正しい境界を保証する値とはしない。今回の素材を見て修正した条件である。

### 1話者だけの対照

元の共有素材から同じ人の3発話を取り、100msの間隔で連結した約6.75秒の対照を1回実行した。
SCDによる話者交代の確定0、候補話者1。無音終端と停止で2区間を出し、CER0だった。
100msの人工gapだけでなく元の発話の無音も残るため、完全な無音なし素材とは扱わない。

### 境界の単体検査

Flutter testで、一度だけ現れる偽の変化では確定しないこと、窓のローカル番号が反転しても
境界位置を扱えること、確定後に音声サンプルを重複・欠落させないこと、VAD/停止の二重flushをしないこと、
純粋な無音をASR区間にしないこと、8秒を越えて窓が移動しても音声を一度ずつ送ることを確認した。
偽predictorによる境界管理の検査で、モデル精度を証明するものではない。

### 結果回収の修正

`open --stdout` が既存ログへ追記し、初回の回収scriptがJSON2件を検出して停止した。
古い数値を最新結果としないよう、追記された2件は既知の試行と照合し、最新試行を回収した。
再現taskは各試行の専用ログを先に空にし、JSONが1件であることを検査する。

## 再現と証拠

```sh
# 実マイクは開かない。比較2条件と1話者対照を実推論する
mise -C 2026/10/19/apple-speech-scd-asr run streaming-check
# 保存結果だけの検算
mise -C 2026/10/19/apple-speech-scd-asr run
# 改良版を実マイクで体験
mise -C 2026/10/19/apple-speech-scd-asr run demo
```

- `results/online-baseline.json` / `online-streaming.json`: 旧方式と改良版の共有素材。
- `results/online-one-speaker.json`: 同じ人だけの対照。
- `results/online-comparison.json`: 全文CER、6発話末尾の時刻、区間の混入、候補IDの対応。
- `tools/validate_streaming.py`: 期待文は評価にのみ使い、推論へ渡さない。
- `app/test/streaming_scd_test.dart`: 境界管理の単体検査。

期待境界は以前のSCD結果を使う近似で、正しい単語時刻のgold corpusではない。
最後の文字の比較は編集整列に依存するので、欠落がある方式ではCERと必ず併記する。
モデルの話者番号の正解、同時発話・3人以上・雑音、長時間は未検証。体験の性能については以下の本人評価を参照。
逐次方式は話者変化で区間を切る方式で、区間内の重なり音声の分離や、すべての非話者フレームの除外はしない。
SCDが境界を見逃せば、複数人物を含む音声が同じASR要求へ入り得る。
実マイクの音声・会話文は保存せず、結果JSONの文字は共有素材だけ。prototypeは未変更。
